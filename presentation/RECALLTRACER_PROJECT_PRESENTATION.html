01 / The problem

When complaints arrive, the product is only the beginning.

01 · FIND THE SOURCE

Different products

Three incidents may point to a shared ingredient hidden behind different production batches.

02 · AVOID OVERREACTION

Common ingredients

A ubiquitous ingredient can match every complaint and still be too broad to justify a recall.

03 · LIMIT EXPOSURE

Silent inventory

Affected stock may remain on shelves at stores where nobody has complained yet.

The core problem is not just finding similar reports. It is reconstructing the connected path from source lot to affected shelf.
02 / Why a graph?

The investigation is a path through the business.

Supplier → ingredient lot → production mix → finished batch → store → shelf → associate

Graph databases make these links explicit and make bounded multi-hop traversal a first-class query.

03 / Graphs for agents

Agents need a connected world—not just relevant text.

PROBLEM

LLMs reason from context

Without explicit relationship data, an agent can confuse similarity with proof or miss a chain of intermediate production steps.

GRAPH CAPABILITY

Traverse known relationships

Ask which lots reach these batches, through which mixes, and where the resulting products were delivered.

AGENT BENEFIT

Return auditable evidence

Give the agent concrete paths and structured results it can explain, rather than asking it to invent connections.

Lot→Mix→Batch→Store
In RecallTracer, the graph answers “How are these entities connected?” Similarity search can help find relevant reports, but it cannot verify the supply-chain path by itself.

Graphs do not replace relational or vector databases: they make connected-path questions explicit and inspectable.

04 / Graph-backed agent memory

Remember a confirmed finding as connected knowledge.

MEMORY LOOP

Write once, retrieve by graph identity

  1. Investigation is reviewed and confirmed by a human.
  2. A Finding stores the root-cause lot and links to affected batches.
  3. A later complaint traces upstream lots and checks for matching findings.
  4. A match returns prior evidence and can skip candidate ranking.
This is explicit, entity-linked memory in FalkorDB—not a vector embedding or hidden model memory.

06 / Agent + evidence

The LLM orchestrates. The graph grounds.

THE AGENT

Interprets and coordinates

Understands complaints or supplier notices, selects tools, follows workflow steps, and explains results.

THE GRAPH + TOOLS

Return inspectable facts

Resolve entity IDs, traverse production paths, inspect deliveries, score candidates, and return structured rows.

User prompt→ LangGraph agent→ Typed tools→ FalkorDB→ Evidence + next step
The model does not invent the supply-chain path or calculate the recall score from prose. It uses bounded tools over structured data.

Previously confirmed root cause

Recall the human-approved finding for groundnut-oil lot GO-0611 and explain the Pune complaint using that saved evidence.

SKIP THE RE-RUN

No fresh attribution sweep

No rank_lots at depth 1 or 2, no candidate re-scoring, and no repeated full investigation flow.

The agent still verifies the batch-to-lot connection and looks up the finding. Memory avoids repeating the expensive reasoning path—not the evidence check.

The takeaway

Give agents a world they can navigate—and evidence they can show.

RecallTracer combines graph traversal, deterministic reasoning, agent orchestration, and human authorization to make incident response traceable from source lot to store shelf.
